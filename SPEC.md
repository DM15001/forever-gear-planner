# Forever Gear Planner — SPEC

Private gear-planning site for World of Warcraft: Forever. Static web app, English UI, no backend.
First target: **Enhancement Shaman, pre-raid (phase 1), level 60**.

## Goal

Paste a character export, see current gear next to BiS and alternatives per slot, see which
items/enchants are upgrades and where they come from, and get a farm order by dungeon and boss.

## Out of scope for v1

- Other classes/specs (add later as data files, no code changes)
- Raid gear, phase 2+
- Running the sim inside the page (see Milestone 7)
- Accounts, server, database

## Stack

- Vite + React + TypeScript, static build, deployable to GitHub Pages unchanged
- Character and settings stored in `localStorage`
- All game data as JSON in `src/data/`, generated by a script, never hand-edited

## Data source

`github.com/wowsims/forever` (MIT). It asks for a user-visible link back: put
"Data and stat weights from WoWSims" with a link in the footer.

`assets/database/db.json` contains (checked 2026-11-21):

| Key | Count | Used for |
|---|---|---|
| `items` | 7,415 | id, name, icon, type (slot), armorType, weapon fields, reqLvl, quality, phase, stats, sources, set, item effects |
| `enchants` | 248 | effectId, name, slot type, stats, sources |
| `zones` | 105 | zone/dungeon names |
| `npcs` | 865 | boss names, `zoneId` |
| `factions` | 15 | reputation sources |

Item stats: `scalingOptions["0"].stats` is a map of stat index -> value. Indexes are the `Stat`
enum in `proto/common.proto` (0 Strength, 1 Agility, 2 Stamina, 3 Intellect, 5 SpellDamage,
10 NatureDamage, 12 SpellPiercing, 14 AttackPower, 17 Hit, 18 Crit, 19 Haste, 20 ArmorPen,
21 Expertise). Hit, crit and haste are single ratings shared by melee and spells.

Item slot: `type` = `ItemType` enum (1 Head ... 11 Finger, 12 Trinket, 13 Weapon, 14 Ranged).
Armor: `armorType` 1 Cloth, 2 Leather, 3 Mail, 4 Plate.

Item sources, one of:

- `drop`: `{ npcId, zoneId, difficulty, otherName?, category? }` (`otherName` e.g. "Trash")
- `quest`: `{ id, name, faction }`
- `crafted`: `{ profession, spellId }`
- `rep`: `{ repFactionId, repLevel, factionId }`
- `soldBy`: `{ npcId, npcName, zoneId, faction }`
- `pvp`: `{}`

**Not in the data: drop chances.** Add later as a manual `dropChances.json` (itemId -> percent).

## Character input

Paste the JSON from the WoWSims Exporter addon. Fields the sim's own importer reads:

```json
{
  "flavor": "forever",
  "version": "...",
  "class": "shaman",
  "race": "...",
  "level": 60,
  "talents": "..-..-..",
  "professions": [{ "name": "...", "level": 300 }],
  "gear": { "items": [{ "id": 227021, "enchant": 2543 }, null, { "id": 15411 }] }
}
```

- `gear.items` is ordered by slot; entries can be `null` or `{}`.
- Unknown item id: keep the id, show "Unknown item", link to Wowhead anyway.

Second accepted format: the sim's own JSON export (a `RaidSimRequest`). The player sits at
`raid.parties[0].players[0]` with `race` ("RaceOrc"), `class` ("ClassShaman"),
`equipment.items`, `talentsString`, `profession1`, `profession2`. Detect the format by the
presence of `raid` vs `gear`.

Slot order, confirmed against a real export (17 entries, same in both formats):
Head, Neck, Shoulder, Back, Chest, Wrist, Hands, Waist, Legs, Feet, Finger1, Finger2,
Trinket1, Trinket2, MainHand, OffHand, Ranged (totem). OffHand is `{}` with a two-hander.

Manual overrides (required, exports can be wrong):

- Race: the sim export carried the wrong race. Race drives faction filtering and racial
  bonuses (Dwarf: +1% hit, so 7% needed from gear instead of 8%).
- Professions: the sim export carried the sim's default professions, not the character's.
- Enchants: the sim export carried the preset's enchants. Offer "clear all enchants" and
  per-slot enchant editing.
- Random-suffix items ("... of the Eagle") arrive without their suffix and score 0. Let the
  user pick the suffix (`randomSuffixOptions` on the item, `randomSuffixes` in the db).

## Scoring (v1)

Equivalence points: `score = sum(stat * weight) + mainHandDps * mhDpsWeight`.

Default weights = WoWSims "Pre-BiS" preset for Enhancement
(`ui/specs/shaman/enhancement/presets.ts`):

| Stat | Weight |
|---|---|
| Main-hand DPS | 14.18 |
| Hit rating | 5.2 (below the 8% cap) |
| Expertise rating | 3.5 |
| Haste rating | 2.81 |
| Spell piercing | 2.52 |
| Crit rating | 2.42 |
| Strength | 2.2 |
| Intellect | 1.99 |
| Agility | 1.32 |
| Spell damage | 1.27 |
| Attack power | 1.0 |
| Nature damage | 0.72 |
| Armor penetration | 0.37 |

- Weights are editable in the UI and saved; a "reset to WoWSims default" button restores them.
- Hit: count the 5.2 weight only up to the cap for the whole set, lower weight beyond it.
- Items with procs, on-use effects or set bonuses (`itemEffects`, `setId`) get a
  "score incomplete, sim it" badge. EP cannot value them.

Lessons from the first test run against a real character:

- Ranking each slot on its own overvalues hit: almost every top alternative carries 10 hit
  rating, and together they overshoot the cap. Rank per slot for display, but compute the
  set total with the cap applied and show "hit over cap: X".
- About 30% of items have no source in the db, mostly new Forever items. Show "source
  unknown" and allow a manual `sourceOverrides.json`.
- Add filters: hide PvP-rank gear, hide gear from raids, hide professions the character
  does not have, hide the other faction's quest rewards.
- Ranged slot: only totems for Shaman (`rangedWeaponType`), never bows or guns.
- Main hand: two-handed axe, mace or staff. Shaman cannot dual wield in Forever.

## Tabs

1. **Character** — paste export, 17 slots with icon, name, enchant, score, Wowhead link.
   Missing enchants are flagged.
2. **Upgrades** — per slot: current item, BiS, alternatives sorted by score delta.
   Clicking an alternative swaps it in ("what if") and updates total score and hit %.
3. **Farm plan** — upgrades grouped by dungeon -> boss, each dungeon ranked by summed score
   delta of what it can drop. Separate lists for quest, crafted, reputation, vendor.
4. **Enchants & professions** — best enchant per slot by score; items and enchants unlocked
   by the character's professions.

## Milestones (one per coding session)

1. **Data script — DONE.** `npm run build-data` runs `scripts/build-data.mjs` (plain Node,
   no dependencies). It downloads `db.json` from wowsims/forever (or takes `--db <path>`) and
   writes `src/data/`: `items.json`, `enchants.json`, `zones.json`, `npcs.json`,
   `randomSuffixes.json`, `meta.json`. Filter: released phase, reqLvl <= 60, uncommon or
   better, equippable by the spec in `src/specs/<spec>.json`. Re-run it to pick up upstream
   changes. See "Generated data" below for the file shapes.
2. **App shell + import — DONE.** Vite + React + TypeScript. `src/lib/importCharacter.ts`
   parses both export formats (pure function, tests next to it). The character is saved in
   `localStorage`. Race, professions and per-slot enchants are editable; "Remove all
   enchants" clears what a sim export filled in. The page is laid out like the in-game
   character pane (`SHEET_LAYOUT` in `src/lib/constants.ts`).
3. **Character tab — DONE.** Each slot shows icon, name (linked to
   `wowhead.com/forever/item=<id>`), stats, first source, enchant and random-suffix
   pickers. The centre panel shows gear stat totals and hit against the cap, including the
   racial bonus. Logic is in `src/lib/stats.ts` (pure, tested). Icons come from
   `wow.zamimg.com/images/wow/icons/large/<icon>.jpg`; hover tooltips from Wowhead's
   `tooltips.js` (loaded in `index.html`). Both are the same sources the WoWSims UI uses.
   Look and feel: dark, armory-like, the game's quality colours and gold. No Blizzard or
   Wowhead logos or artwork beyond item icons.
4. **Scoring + Upgrades tab — DONE.** `src/lib/scoring.ts` (pure, tested): `scoreSet`
   scores a whole set with hit capped (racial included, over-cap weight from the spec
   config); `slotCandidates` ranks every obtainable item for a slot by set-score change;
   `suggestPlan` makes the single best swap repeatedly until none helps. The plan
   (`character.plan`, slot index -> item id) is saved with the character. Filters by source
   kind; faction and required profession are applied automatically. Not done yet: editing
   the weights in the UI, filtering crafted items to the character's own professions.
5. **Farm plan tab**.
6. **Enchants & professions tab**.
7. **Real sim (optional)** — the repo ships a CLI (`cmd/wowsimcli`) and a WASM build
   (`sim/wasm`). Step one: an "Open in WoWSims" export of the what-if set. Step two: run the
   WASM sim in a web worker for exact DPS deltas.
8. **GitHub Pages** — public repo or paid plan needed for Pages; add the WoWSims attribution.

## Generated data (`src/data/`, never hand-edited)

- `items.json` — `{ id, name, icon, slot, armorType?, rangedType?, quality, ilvl, reqLvl?,
  stats: { strength, hitRating, ... }, weapon?: { type, hand, speed, dps, damageMin,
  damageMax }, unique?, faction?, requiredProfession?, setId?, setName?, effects?: [...],
  randomSuffixOptions?, randPropPoints?, sources?: [...] }`.
  `slot` is one of head, neck, shoulder, back, chest, wrist, hands, waist, legs, feet,
  finger, trinket, weapon, ranged. Missing keys mean "none".
- Source kinds: `drop` (`zoneId`, `npcId?`, `otherName?`, `zoneKind`: dungeon | raid | world),
  `quest` (`questId`, `name`, `faction?`), `crafted` (`profession`, `spellId`),
  `rep` (`repFaction`, `repLevel`), `vendor` (`npcName`, `zoneId`, `faction?`), `pvp`.
- `enchants.json` — `{ effectId, itemId, spellId, name, icon, slots: [...], stats, hasEffect,
  effects?, sources? }`. `effectId` is the id used in character exports.
- `zones.json` — `{ id, name, kind }`. `npcs.json` — `{ id, name, zoneId }`.
- `randomSuffixes.json` — `{ id, name, stats }`; item stat =
  `floor(randPropPoints * suffixStat / 10000)`.
- `meta.json` — build time, upstream commit, counts.
- Upstream marks unreleased content (raids, old PvP ranks) as "phase unknown"; the script
  drops it. When the raids open, re-run the script and check `meta.json` counts.

Spec config lives in `src/specs/enhancement-shaman.json` (equippable types, hit cap, rating
conversions, racial bonuses, default weights). The script and the app both read it.

## Rules for the AI coding assistant

- One milestone per session. Do not start the next one unasked.
- No game data hard-coded in components. Everything comes from `src/data/`.
- Spec/class specifics live in one config file (`src/specs/enhancement-shaman.json`) so new
  specs are config, not code.
- Parser, scoring and farm ranking are pure functions with unit tests.
